# Мой Сосновый Бор

Основа авторского сайта о Сосновом Боре для курса «Верстка и прототипирование сайтов».
Реализованы главная страница, история города с пятью фотографиями, подборка мест
для прогулок и раздел учебных работ. История основана на материалах администрации,
а фотографии с Wikimedia Commons сопровождаются авторством и лицензиями.

## Запуск

Требуются Node.js 22.12+ (рекомендуется 24 LTS) и pnpm 11.19.0.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

## Команды

| Команда         | Действие                                        |
| --------------- | ----------------------------------------------- |
| `pnpm dev`      | Сервер Vite с обновлением при изменении файлов  |
| `pnpm build`    | Проверка TypeScript и сборка в `dist/`          |
| `pnpm preview`  | Просмотр собранного сайта                       |
| `pnpm check`    | Типы, ESLint, Stylelint и форматирование        |
| `pnpm lint`     | Проверка кода и CSS                             |
| `pnpm lint:fix` | Исправление правил линтеров, включая сортировку |
| `pnpm format`   | Форматирование файлов через Prettier            |
| `pnpm fix`      | Исправление линтеров и форматирование           |

## Структура FSD

```text
src/
  app/       # запуск приложения, маршруты, общий layout и глобальные стили
  pages/     # страницы: home, about, places, practice, task-01, not-found
  widgets/   # общие блоки: site-header и site-footer
  entities/  # city: история, места, источники, фотографии и компонент CityPhoto
  shared/    # универсальные компоненты: container, logo, page-intro
  main.tsx   # точка входа
```

Слой `features` добавляется при появлении соответствующих сценариев.
Алиас для него уже настроен; пустые каталоги не создаются.

Слайсы страниц и виджетов имеют публичный API в `index.ts`. Импортируйте другие
слайсы через этот файл, например `@pages/home` или `@widgets/site-header`.
Внутри одного слайса используйте относительные импорты.

Зависимости направлены вниз: `app → pages → widgets → features → entities → shared`.
Можно пропускать слои. Импорты соседнего слайса того же слоя запрещены.
Правило ESLint проверяет направление импортов по алиасам; оно не является полной
проверкой FSD и не анализирует обходы через относительные пути или глубокие импорты.

## Алиасы

`@app/*`, `@pages/*`, `@widgets/*`, `@features/*`, `@entities/*`, `@shared/*`
одинаково настроены в Vite и TypeScript. IDE использует `tsconfig.app.json`.

```tsx
import { SiteHeader } from '@widgets/site-header';

import { Container } from '@shared/ui/container';
```

## Проверки и стиль

- ESLint: TypeScript, React Hooks, React Refresh и базовые направления FSD-импортов.
- `eslint-plugin-simple-import-sort`: сортирует импорты и экспорты.
- Порядок групп: побочные эффекты, Node.js, внешние пакеты, FSD-слои сверху вниз,
  относительные импорты, CSS. Имена внутри групп сортируются автоматически.
- Импорты типов выделяются через `import type`.
- Stylelint: стандартные правила CSS и алфавитный порядок свойств.
- Prettier: форматирование TS/TSX, CSS, JSON, Markdown и конфигурации.
- `.editorconfig`: UTF-8, LF, отступ в два пробела.

Prettier отвечает за форматирование, ESLint — за сортировку импортов. Для полного
автоисправления запускайте `pnpm fix`. В IDE можно включить ESLint fix и Prettier
при сохранении файла.

## Страницы и размещение

Маршруты: `/`, `/about`, `/places`, `/practice`, `/practice/task-01`.
Неизвестные адреса показывают страницу 404 внутри приложения.
На всех страницах присутствуют шапка, меню, `main` и подвал.
Логотип размером 48×48 px нарисован только CSS.

Используется HashRouter: адреса имеют вид `/#/about`, поэтому прямой переход
и обновление страницы работают на статическом хостинге без SPA-перенаправлений.
Production base задан как `/politech-verstka/` под существующий GitHub-репозиторий.
При смене имени репозитория измените `base` в `vite.config.ts`.

## Публикация на GitHub Pages

Workflow `.github/workflows/deploy.yml` запускается при push в `master`,
при pull request в `master` и вручную из вкладки Actions. Он устанавливает
Node.js 24 и версию pnpm из `packageManager`, ставит зависимости по lockfile,
выполняет `pnpm check` и `pnpm build`. После успешных проверок ветка `master`
публикуется на GitHub Pages. Pull request проходит проверки без публикации.

Однократная настройка репозитория:

1. Открыть **Settings → Pages** репозитория `GalichAnton/politech-verstka`.
2. В блоке **Build and deployment** выбрать **Source → GitHub Actions**.
3. Открыть **Actions → Check and deploy to GitHub Pages → Run workflow**,
   выбрать ветку `master` и запустить workflow.
4. Дождаться успешного завершения заданий `Check and build` и `Deploy to GitHub Pages`.

Адрес после успешного деплоя: <https://galichanton.github.io/politech-verstka/>.
При следующих push в `master` сайт обновится автоматически. Отдельная ветка
`gh-pages` и токен в Secrets для этого workflow не требуются.

## Контент и фотографии

Данные находятся в `src/entities/city/model/`, фотографии — в `src/entities/city/assets/`.
Импорты изображений обрабатывает Vite, поэтому пути работают как в dev-режиме,
так и в подпапке репозитория на GitHub Pages. Изображения хранятся локально:
при открытии сайта загрузка с Wikimedia не требуется.

Фотографии уменьшены и преобразованы в WebP без ретуши. Авторы, оригиналы,
лицензии и сведения об обработке перечислены в [docs/content-sources.md](docs/content-sources.md)
и в подписях на страницах. Даты съёмки взяты из метаданных Wikimedia Commons;
снимки разных лет не обозначены как актуальное состояние объектов.
